## 5. 반복 분야와 연결되는 주제

- 대외활동/부스트캠프·학교생활과 프로젝트 기록은 기술 레퍼런스와 읽는 목적이 다르므로 경험·기록 안에 둔다.

## 11. Article layout

데스크톱: 왼쪽 문맥 탐색 / 중앙 본문 / 오른쪽 TOC. 본문 제목·설명·날짜·태그·시리즈 순서를 표시한다. 본문 최대 너비 약 48rem, 16–17px 본문, 코드 가로 스크롤, 얇은 구분선과 작은 모서리를 사용한다. 본문 h1도 많으므로 h1이 포함된 글만 원문을 수정하지 않고 렌더링 시 heading을 한 단계 낮춰 페이지 제목 h1과 구별한다. h2 이하로 시작하는 글의 단계는 유지한다. TOC는 글에서 사용한 최상위 두 단계 중심, 더 깊은 heading은 접기 영역에 둔다. heading 없는 13개 글은 빈 TOC를 만들지 않는다. 모바일 TOC는 본문 앞 details로 둔다. 이전/다음은 원본 시리즈 index 기준, 관련 글은 태그 교집합과 같은 카테고리에 근거해 최대 3개 제시한다.

## 13. 구현 architecture

정적 Astro + strict TypeScript + Tailwind Vite plugin + Content Collections. 125개 원문은 .md로 저장하고 MDX는 새 글의 Photo component 사용을 위해 지원한다. React가 꼭 필요한 기능은 현재 없으므로 검색 dialog·theme·lightbox는 native dialog와 작은 TypeScript로 구현한다. 로그인/DB/게시글 API는 만들지 않는다.

라우팅: /, /archive/, /series/, /series/[slug]/, /category/, /category/[slug]/, /tags/, /tags/[slug]/, /blog/[slug]/. 원문 slug를 metadata로 보존하고 URL 경로는 encodeURIComponent로 안전하게 생성한다. Pagefind는 정적 build 후 본문을 색인하고 검색할 때만 로드한다.

원문 수집→JSON snapshot→검증 가능한 frontmatter+본문→Content Collections→정적 HTML→Pagefind. 빌드는 Velog API를 호출하지 않는다. 이미지/R2 credential과 개인 도메인이 없으므로 manifest와 다운로드/업로드/매핑 workflow, 환경변수 문서까지만 구성한다. 이미지의 완전한 독립과 실제 도메인 전환은 설정 후 별도 검증이 필요하다.

공식 기술 근거: [Astro Content Collections](https://docs.astro.build/en/guides/content-collections/), [Astro 7 변경 사항](https://docs.astro.build/en/guides/upgrade-to/v7/), [Tailwind Astro 설치](https://tailwindcss.com/docs/installation/framework-guides/astro). npm registry 조회 결과 Astro 7.3.1, MDX 8.0.0, Tailwind 4.3.3, Pagefind 1.5.2를 확인했다. Astro 7 기본 Markdown 처리기 변경에 대응하여 기존 remark/rehype 보존 검증에 적합한 공식 unified processor를 사용한다.

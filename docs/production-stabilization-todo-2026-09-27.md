# 프로덕션 안정화 및 후속 개선 투두 — 2026-09-27

## 목적과 현재 상태

기능 추가보다 권한 통제, 데이터 복구, 콘텐츠 일관성, 배포 복구를 먼저 확보한다. 그다음 측정한 병목을 줄여 성능과 운영 비용을 개선한다.

- 계획 작성 이후 A1 백업·복구와 A2 인증 구현·검증을 완료했다. 다른 계정·만료 세션은 인증 핸들러 런타임에서 확인했으며, Cloudflare 원격 D1을 이용한 같은 검증은 현재 권한 오류로 보류 중이다.
- 기존 구현에 있는 본인 계정 검사, Markdown 정제, SQL bind, revision/중복 요청 방어, 이미지 참조 확인은 유지한다. 같은 기능을 새로 만드는 작업으로 잡지 않는다.
- 분석에서 실제 계정 침해나 토큰 탈취를 확인한 것은 아니다. 일부 코드상의 위험과 운영 응답을 확인했으며, 전체 보안·복구·성능을 보증한 상태는 아니다.
- 현재 청구액, 계정 플랜, D1/R2 실제 크기, endpoint별 CPU·DB 읽기량은 아직 확인하지 않았다.
- 실행 순서는 이 문서를 기준으로 한다. 기존 분석 문서의 항목별 우선순위는 근거로 보존한다.
- 과거 글쓰기 의사 결정 문서는 당시 Git/Decap 방식의 역사 기록이다. 현재 D1 방식의 실행 계획으로 사용하지 않는다.
- 2026-09-28에 D1 상세 페이지에서 기존 시리즈 전체 글 페이지네이션이 누락된 회귀를 확인했다. A3의 첫 작업으로 복원한다.

## 확정한 방향

1. Astro + 사이트/CMS Workers + D1 + R2 + GitHub Actions를 유지한다.
2. 첫 실행은 실제 운영 데이터의 백업·복구 확보다. 가장 먼저 바꿀 주요 코드 영역은 인증이다.
3. D1을 운영 콘텐츠의 기준으로 삼고 레거시 Git 편집·정적 검색 fallback을 정리한다.
4. GitHub는 본인 확인에 필요한 최소 권한으로 사용한다. 브라우저에 GitHub access token을 전달하지 않는다.
5. 서버에서 폐기 가능한 자체 세션으로 관리 기능을 인증한다.
6. 이미지 자동 정리의 7일 유예, 삭제 직전 최신 참조 확인, 확인 실패 시 삭제 중단을 유지한다.
7. 공개 캐시는 발행·수정·삭제·복원에 대한 무효화 설계와 함께 적용한다.
8. 저장소 private 전환과 유료 플랜 전환은 아직 확정하지 않는다. 영향과 실제 사용량을 확인한 뒤 결정한다.
9. 새로운 DB, Redis, Queue, 외부 모니터링 구독을 먼저 추가하지 않는다. 기존 기능과 플랫폼 수단을 우선 활용한다.

## A. 먼저 끝낼 안정화 작업

아래 A1–A4가 첫 안정화 범위다. 시리즈 목록 복원은 기존 기능의 회귀 수정으로 A3에 포함한다. 새 기능 요청과 후속 최적화는 별도 목록에 둔다. 각 단계에서 필요한 검증과 기록까지 끝낸 뒤 다음 단계로 이동한다.

### A1. 운영 백업과 복구 확보

근거: 장기 운영 문서의 데이터 보호 계획. SQL만으로 삭제된 R2 이미지는 복구할 수 없다.

- [x] 현재 운영 D1의 실제 SQL 백업을 확보한다. Git에서 초기 적재 파일을 만드는 도구와 구분한다.
- [x] 글·초안·시리즈와 이미지 참조가 백업에 포함되는지 확인한다.
- [x] 이미지 복구 기간을 정하고, 필요한 R2 사본과 보관 위치를 확보한다. 7일 미사용 삭제 유예와 백업 보관 기간은 별개로 관리한다. 주간 최근 4회·월간 최근 12개 정책을 도구에 기록하고 자동 실행을 확인했다.
- [x] SQL·초안·세션 정보가 공개 버킷이나 공개 저장소에 노출되지 않게 보관한다. 복구된 세션은 활성화하지 않는다.
- [x] 운영 DB를 덮어쓰지 않는 별도 환경에서 글·초안·시리즈 및 대표 이미지를 복구한다.
- [x] 백업 생성·복구 명령, 보관 위치, 실패 대응을 실행 문서로 기록한다. 비밀값은 기록하지 않는다.
- [x] 주간 최근 4회·월간 최근 12개 독립 SQL·이미지 암호화 사본 보관을 확정하고, 기존 GitHub Actions/R2로 자동화했다.

**완료 조건:** 실제 운영 백업으로 별도 환경의 콘텐츠와 대표 이미지를 복구한 근거가 있다. 복구 가능한 기간과 이미지 복구의 한계를 문서에서 알 수 있다.

### A2. 인증과 세션 통일

근거: 보안 S01/S02/S04, 성능의 반복 GitHub 인증 조회.

- [x] 같은 origin의 로그인·콜백·관리 API 흐름을 정리하고 host-only HttpOnly 세션으로 통일한다. 가능한 경우 `__Host-` 쿠키 조건을 적용한다.
- [x] 무작위 세션 ID와 서버 레코드로 만료·폐기를 처리한다. 원본 세션 ID를 로그에 남기지 않는다.
- [x] 본인 계정 검사, OAuth state, 정확한 메시지 origin/source 검사와 변경 요청 Origin/CSRF 방어를 유지한다.
- [x] GitHub 토큰의 팝업 전달과 sessionStorage 보관을 없앤다.
- [x] 관리 API의 별도 GitHub Bearer 인증 경로와 광범위한 Domain 쿠키를 제거한다.
- [x] OAuth의 요청 scope를 `read:user`로 축소했다. 남아 있는 Git 편집 코드는 D1 모드에서 사용되지 않으며 A3와 함께 제거한다.
- [x] 로그아웃 시 서버 세션을 폐기한다. 로그아웃 뒤 편집 API 세션 확인이 401을 반환하는 것을 확인했다.
- [x] 기존 넓은 권한 토큰 폐기와 `read:user` 재동의를 완료했다.
- [x] 비로그인 상태의 세션·관리 API 거부를 확인했다.
- [x] 다른 계정과 만료 세션을 거부하는 인증 핸들러 런타임 확인을 끝냈다. 로그아웃 세션도 폐기된다. Cloudflare 원격 D1에 테스트 행을 넣는 추가 검증은 권한 오류 해소 후 재실행한다.
- [x] 정상 관리 API가 요청마다 GitHub `/user`를 재호출하지 않는다. `/user` 조회는 OAuth 콜백에만 있다.

**완료 조건:** 브라우저에 GitHub 토큰이 없고 본인 서버 세션만 관리 API를 사용한다. 로그아웃한 세션과 이전 인증 경로는 거절된다. 로그인·발행·업로드가 정상 동작한다.

**검증 기록 — 2026-09-28:** 스테이징에서 본인 OAuth 로그인 후 임시 글 발행, 합성 PNG 업로드와 이미지가 포함된 글의 공개 렌더링을 확인했다. 테스트 글은 스테이징 휴지통으로 이동했고 공개 글 주소는 404가 됐다. 업로드 이미지 객체는 스테이징 R2에서 200으로 응답한다. 7일 정책을 지키기 위해 수동 영구 삭제하지 않았다. 로그아웃 직후 스테이징 `/api/auth/session`은 401, `/admin/`은 로그인으로 302 이동했다. 비로그인 관리 API와 임의 Bearer만 보낸 관리 API는 각각 401이었다. 프로덕션 비로그인 `/api/auth/session`은 401, `/write/`는 로그인으로 302 이동했다. 스테이징은 `STAGE_EDITOR_PREVIEW` 설정 때문에 비로그인 `/write/` 요청에 HTML을 200으로 반환하지만, 편집기 클라이언트는 인증 확인 뒤 로그인 화면으로 이동하며 관리 API는 세션 없이는 401을 반환한다. 합성 세션 행을 사용해 배포된 CMS의 세션 핸들러를 메모리 D1 바인딩으로 실행한 결과 허용 계정 204, 다른 계정 401, 만료 세션 401, 비로그인 401을 확인했다. Cloudflare 원격 D1에 같은 테스트 행을 넣는 검증은 Wrangler의 현재 자격 증명이 D1 접근을 거부해 수행하지 못했다(Cloudflare API 오류 7403). 해당 행은 삽입되지 않았다.

### A3. 콘텐츠 기준 통일과 변경 결과 보장

근거: 확인된 시리즈 목록 누락, 보안 S03/S07, 성능의 불필요한 정적 산출물. 현재 삭제 글 노출 사례를 발견한 것은 아니다.

#### A3.1. 시리즈 전체 글 목록과 페이지네이션 복원 — 구현·로컬 검증 완료, 배포 확인 대기

- [x] D1 글 상세 페이지에 기존 시리즈 전체 글 목록을 복원한다. 기존 디자인 자산과 `SeriesPostPagination`의 동작을 우선 재사용한다.
- [x] 한 페이지에 4개씩 표시하고 이전·다음·페이지 번호 이동을 제공한다. 처음에는 현재 글이 있는 페이지를 표시하고 현재 글을 구분한다.
- [x] D1의 공개 글만 최신순으로 표시한다. 시리즈 없는 글에는 목록을 표시하지 않고, 초안·휴지통 글은 제외한다.
- [x] 긴 시리즈에서도 전체 본문이나 전체 사이트 글을 내려받지 않는다. 기존 공개 목록 API와 정렬 방식을 활용한다.
- [ ] 시리즈 변경·글 발행·삭제·복원 후 목록과 현재 글 표시가 맞는지 별도 환경에서 확인하고, 배포 후 공개 상세 페이지에 복원됐는지 확인한다.

## B. 안정화 다음에 실행할 성능·비용 작업

- [ ] 관리 목록에 서버 페이지네이션·검색·필터·전체 집계를 적용한다. 상태별 500개 제한 때문에 글이 누락되지 않게 한다.

**완료 조건:** 글 수가 많아져도 관리할 수 있고 한 페이지 규모만 전송한다. 편집 진입과 입력에 불필요한 전체 작업이 없다. 실제 목록 누락이 발생하면 B2를 안정화 작업으로 앞당긴다.

- [ ] 태그 관계 집계를 화면에 필요한 범위로 제한하고 재사용한다.

## 채택한 수동 요청 처리 절차

1. `me@seungjun.sh`에서 접수일, 답장 주소, 요청 종류와 범위를 확인한다. 첫 답변에서 접수 사실과 확인할 내용을 알린다. 이메일 주소가 GA 브라우저 식별자라고 간주하지 않는다.
2. 대상 브라우저의 기존 식별자로 데이터 연결이 가능한지, 다른 사람의 데이터를 노출할 위험이 없는지 확인한다. 필요한 최소 정보와 안전한 확인 방법을 먼저 설명한다. 주민등록번호·신분증 사본·인증 토큰·전체 쿠키 덤프를 일괄 요구하지 않는다. 식별을 위해 새 분석 수집을 시작하거나 다시 동의하도록 요구하지 않는다.
3. 열람·삭제·처리정지 중 실행 가능한 범위를 확인한다. Google이 제공하는 식별자 기반 조회·삭제 기능, 운영자 권한과 대상 데이터가 맞는지 확인한 뒤 해당 요청에 필요한 조치를 수행한다. 지금은 실제 요청을 처리하거나 GA 설정·데이터를 변경하지 않는다.

### 대상 요청 메일만 삭제하는 수동 운영 절차

1. 접수·회신·처리 중 자료는 기존 메일함에서 관리한다. 실제 요청 정보를 이 저장소에 적거나 별도 DB를 만들지 않는다. 첫 답변 목표일과 별도 법적 조치·통지 기한을 기록한다.
2. 종료 때 최소 기록만 남기고 종료일 + 90일을 최종 삭제일로 적는다. 보관 목적이 없어진 첨부·브라우저 식별자는 먼저 없앤다. 종료하지 않은 Google 처리 작업은 별도로 추적한다.
3. 월 1회 다음 확인일까지 기한에 도달할 자료를 미리 정리한다. 받은편지함뿐 아니라 대상 요청의 보낸 메일·임시보관·보관 폴더, 다운로드 첨부·내보낸 파일·공유 링크·예약 발송·로컬 사본도 실제 사용 범위에서 확인한다. 다른 대화가 섞인 전체 스레드나 휴지통 전체를 선택하지 않는다.
4. [Apple 일반 삭제 안내](https://support.apple.com/en-au/guide/icloud/mm6b1a7ab7/icloud)의 휴지통 최대 30일을 포함한다. 대상만 영구 삭제하는 앱별 조작을 확인하지 못하면 **종료 후 60일을 넘기기 전에 휴지통으로 이동**할 수 있도록, 그 날짜가 다음 월 점검 전에 오는 자료부터 미리 처리한다. 90일째에 휴지통으로 옮기지 않는다. 60일은 새 보관 정책이 아니라 90일 이내 삭제를 위한 여유 기준이다.
5. [Spark 휴지통 설명](https://sparkmailapp.com/glossary/trash-folder)은 휴지통에서 삭제하면 영구 삭제된다고 설명한다. 실제 플랫폼의 개별 선택·영구 삭제 UI와 iCloud 동기화 결과는 미검증이다. 실행 전 대상만 선택 가능한 방법을 확인하고, 일반 Delete가 휴지통 이동인지 영구 삭제인지 구분한다. 전체 계정의 Remove My Data나 Empty Trash를 한 요청의 삭제 수단으로 실행하지 않는다.
6. 현재 사용자 답변은 전달·규칙 없음, Spark 송수신 정도 사용이다. 향후 전달·별도 저장·Spark 서버 기능 사본이 생기면 해당 대상의 삭제 경로도 확인한다. [iCloud 전달 공식 안내](https://support.apple.com/guide/icloud/automatically-forward-email-mm6b1a3960/icloud)의 전체 전달 및 규칙별 전달·원본 유지 옵션과 실제 설정을 대조한다. 설정 변경이나 다른 서비스 접근은 자동 시작하지 않는다.
7. 최소 확인 기록에는 대상 범위·삭제한 저장 위치·시각·미확인 공급자 사본을 적는다. 동기화/서버 백업을 확인하지 못했다면 그 한계를 남긴다. 최종 삭제 확인용 기록에도 개인정보가 있으면 같은 90일 상한 내에서 삭제한다. Apple/Spark 내부 백업을 운영자가 90일 안에 모두 지운다고 약속하지 않는다.

### 브라우저 식별·열람·삭제 절차의 실행 조건

- 이메일은 답장 창구이며 GA의 client ID가 아니다. 기존 브라우저 프로필·사이트 주소·대략적 방문 시기와 요청 범위만 먼저 확인한다. 방문 시각·글 주소만으로 한 사람을 특정하지 않는다. 같은 브라우저를 공유한 사람이나 여러 기기의 자료가 섞일 가능성도 확인한다.
- 웹 Device ID는 client ID라는 [Google 사용자 탐색 설명](https://support.google.com/analytics/answer/9283607?hl=en)을 기준으로 **이미 존재하는** 식별자에 연결 가능한지 검토한다. 기존 쿠키가 없거나 보관이 끝났다면 새 태그 로드·재동의·새 이벤트·User-ID/이메일 수집으로 식별자를 만들지 않는다. `_ga` 전체 덤프나 인증 쿠키를 요청하지 않는다. 기존 쿠키에서 client ID를 안전하게 읽는 구체적 방법/형식과 본인·대리인 확인 기준은 실제 요청 전 확정해야 한다. 식별자 문자열 소지만으로 적법한 본인 확인이 끝난다고 보지 않는다.
- 적법하고 안전한 연결이 되면 해당 속성·해당 식별자 범위에서 사용자 탐색의 사용 가능한 활동을 확인하는 경로가 있다. 실제 조회는 이번에 하지 않았다. 전 계정 보고서·다른 사용자의 활동·추가 식별정보를 답장에 넣지 않는다. 보관 기간·보고 기능·보고 ID·다른 기기 때문에 개인의 모든 방문을 반환할 수 있다고 보장하지 않는다.
- 삭제 실행 경로는 Editor 이상 권한의 사용자 탐색 대상 삭제 또는 [Admin API `properties.submitUserDeletion`](https://developers.google.com/analytics/devguides/config/admin/v1/rest/v1alpha/properties/submitUserDeletion)다. API는 clientId/userId 등 지정 ID를 받으며 응답의 `deletionRequestTime`은 **제출 시각**이다. 현재 v1alpha 문서이며 과거 User Deletion v3 안내는 [이전 안내](https://developers.google.com/analytics/devguides/config/userdeletion/migration)로 연결된다. API 활성화·권한 추가·호출은 하지 않았다. 이메일 기반 필드를 새로 사용하거나 모든 데이터 검색 수단으로 제시하지 않는다.
- 사용자 탐색 공식 설명은 삭제 후 **24시간 내 표시 제외**, **그 다음 63일 내 영구 삭제**로 구분한다. 24시간은 서버 삭제 완료가 아니다. 제출 후 상태/결과의 확인 방법을 확보하고, 확인할 수 없으면 ‘제출됨/공식 처리 기간 경과/공급자 확인 미완료’를 구분해 안내한다. 모든 집계·별도 사본까지 같은 기능으로 삭제됐다고 확대하지 않는다.
- 처리정지·철회는 앞으로의 수집 중단과 기존 데이터 조치를 함께 검토한다. 현재 철회 UI는 미래 수집과 로컬 쿠키만 처리하며 기존 서버 데이터를 자동 삭제하지 않는다. 법 적용 시 필요한 기존 자료 조치와 안전한 식별이 연결되지 않은 점은 출시 전 남은 과제다. 조치 불가를 일괄 면책 문구로 삼지 않는다.

### 공식 법령의 기한·예외 대조

[개인정보 보호법](https://www.law.go.kr/법령/개인정보보호법)과 [시행령](https://www.law.go.kr/법령/개인정보보호법시행령)의 현재 2026-09-11 시행본 해당 조항을 브라우저로 읽었다. 이 개인 블로그의 업무 목적·처리자 지위 및 법률 적용 전체를 확정한 것은 아니다.

- 법 제35조/시행령 제41·42조: 열람 및 연기·거절 통지의 10일 기준. 정당한 연기·제한 사유, 이유와 이의 제기 방법을 확인하고 가능한 부분은 처리한다. 제36조/시행령 제43조: 정정·삭제 조사·조치와 10일 내 결과 통지, 다른 법령이 수집 대상으로 명시한 경우 등의 예외. 제37조/시행령 제44조: 처리정지 및 동의 철회에 필요한 지체 없는 조치와 10일 통지 기준, 법률 의무·타인 이익·계약 관련 예외를 요청별로 확인한다. 시행령 제46조의 본인/정당한 대리인 확인도 적용 여부를 검토한다.
- 10일을 10영업일이나 3영업일 초기 답장으로 대체하지 않는다. 추가 정보 요청이나 Google 처리 대기만으로 원래 수령일을 다시 시작하지 않는다. Google의 기술적 처리 기간이 법정 연기 사유라고 자동 판단하지 않는다. 제한/연기 사유·근거·가능한 부분·후속 일정·이의 제기 방법을 통지하고, me@ 창구에서 재검토 요청을 받을 절차를 둔다.
- 법 제28조의8 국외 이전에는 근거별 요건과 고지 항목이 있다. 항목·국가·시점/방법·수령자 명칭/연락처·목적/보관 기간·거부 방법/효과 등을 실제 조건으로 준비해야 한다. basic 태그 미로딩 선택이나 무료 블로그라는 사실만으로 별도 동의/계약 필요성 근거가 충족됐다고 확정하지 않는다.
- [EDPB 권리 행사 공식 안내](https://www.edpb.europa.eu/sme/be-compliant/respect-individuals-rights_ga)는 GDPR 적용 시 원칙 1개월, 복잡성/요청 수에 따라 추가 2개월 및 첫 1개월 내 사유 통지, 명백히 근거 없거나 과도한 요청의 예외와 합리적 의심 시 최소 추가 본인 확인을 설명한다. 해외 접속 가능만으로 GDPR 적용을 확정하지 않는다. 영토적 적용 범위 자료의 충분한 읽기 확인은 이번에 확보하지 못했으며 다른 국가 법률 전수 검토도 하지 않았다.

- 관리자 세션: 만료 행의 정기 삭제 기준과 실행 방식, 인증 실패 응답 로그 최소화 여부를 정해야 한다. 이번에는 코드 변경하지 않았다.
- 사이트 백업: SQL에 세션/인증 관련 행을 보관할 필요, 주간/월간 사본의 최대 나이와 실패 시 정리, 초기 사본의 목적 종료/최종 삭제일, Time Travel과 복원 후 재유입 방지 및 실제 접근자/키 권한을 정해야 한다. 버킷 lifecycle/백업 스크립트 변경·초기 객체 삭제는 별도 작업이다. 사용자의 외부 저장/공유 없음 답변으로 공급자 내부 복구 사본·접근 권한 확인이 대체되지 않는다.
- 요청 메일: 전달·규칙 없음과 Spark 송수신 정도 사용은 사용자 답변으로 확인됐다. 남은 사용자 사실은 메일 확인 기기와 로컬/다운로드/내보낸 사본·기기 백업 여부다. 앱별 개별 삭제·동기화와 공급자 내부 처리/백업은 별도 미확인이다. 설정 값을 바꾸거나 메일 본문·비밀번호를 제공할 필요는 없다. 이미 답변된 전달·규칙/사용 기능 질문을 반복하지 않는다.
- 별도 분석 검증: 향상된 측정의 실제 자동 매개변수, 쿠키 생성·갱신·철회, Network/DebugView/Realtime 수신은 미실행이다. 향후 명시적으로 승인된 별도 범위에서 기존 운영 ID와 구분한 검증 환경·공개/색인 가능 경로·동의 상태·깨끗한 브라우저 프로필을 먼저 정해야 한다. 이번에 환경을 만들거나 보호 조건을 해제하지 않았다.

공개 초안에는 Spark, 세션/백업의 범위와 미확정 보관, 첫 답변/제출/완료 구분을 최소 반영했다. 실제 국가·수령자·보관·법적 근거를 추정해 채우지 않았다. **전체 법률 준수·출시 준비 완료가 아니며 실제 공개일도 미기입 상태다.** 검증 결과는 각 폴더 계획 문서의 이번 후속 절에 기록하고 인계 갱신 후 멈춘다.
